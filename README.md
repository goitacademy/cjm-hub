# CJM hub

Сховище CJM (Customer Journey Map) курсів GoIT. Кожна CJM — окрема сторінка з власним посиланням. Загального списку сторінок немає.

Адреса сторінки: `https://goitacademy.github.io/cjm-hub/<курс>-<суфікс>/`, наприклад `.../ai-automator-6fc9eb/`.
Випадковий суфікс не дає вгадати адресу іншої CJM.

Усі CJM мають один дизайн. Він лежить у спільному шаблоні. Сторінка курсу містить тільки текст: блоки, ДЗ, підказки, фініш.

## Як працювати з CJM

Відкрийте Claude Code у цьому репозиторії і напишіть, що потрібно. Правила для Claude записані в [CLAUDE.md](CLAUDE.md).

**Додати CJM:**

> Зроби CJM для курсу Python Developer. Ось програма курсу: (вставте текст програми)

Claude створить сторінку і відкриє її в браузері для перегляду. Якщо все добре, напишіть «публікуй». Claude опублікує сторінку і дасть посилання. Сторінка відкривається через 1–2 хвилини.

Дизайн описувати не потрібно: кольори, шрифт і вигляд карток бере шаблон. Потрібні тільки дані курсу:

1. Блоки: назва, кількість тижнів, список ДЗ.
2. Позначка складності блоку та підказка внизу картки, якщо потрібні.
3. Текст вступного блоку, якщо він є.
4. Що буде на фініші.
5. Поради для планування, якщо потрібні.

Кількість ДЗ у блоках і прогрес шаблон рахує сам.

**Змінити CJM:**

> Зміни в CJM курсу AI Automator: у блоці 3 додай ДЗ 16 — Модуль 7. Фінальний проєкт.

Посилання не змінюється.

**Прибрати CJM:**

> Видали CJM курсу AI Automator.

Після публікації посилання дає помилку 404.

## Важливо

- Репозиторій публічний. Не додавайте в CJM персональні дані та внутрішню інформацію.
- Сторінку захищає тільки складне посилання. Хто має посилання, той відкриє сторінку.
- Стара версія CJM залишається в історії git, навіть після видалення.
- Зміна шаблону змінює всі CJM одразу.

## Як це влаштовано

| Шлях | Що це |
|------|-------|
| `site/_shared/cjm.css`, `site/_shared/cjm.js` | Спільний шаблон: дизайн, картки, галочки, прогрес |
| `site/<курс>-<суфікс>/index.html` | Одна CJM: тільки дані курсу |
| `scripts/new-cjm.sh` | Створює папку для нової CJM з випадковим суфіксом |
| `scripts/check.sh` | Перевіряє CJM перед публікацією |
| `scripts/validate-cjm.js` | Перевіряє дані курсу (використовує `check.sh`) |
| `.github/workflows/deploy.yml` | Після кожного push у `main` запускає перевірку і публікує `site/` на GitHub Pages |

Що перевіряє `scripts/check.sh`:

1. У корені `site/` є тільки папки CJM і шаблон `_shared`.
2. Назва папки має формат `<курс>-<6 символів>`.
3. У кожній папці є `index.html`, і він підключає шаблон.
4. Сторінка має `<meta name="robots" content="noindex, nofollow">`, щоб пошукові системи її не індексували.
5. Дані курсу не мають помилок: немає пропущених обов'язкових полів і невідомих полів.
6. CJM не посилаються одна на одну.

Якщо перевірка не проходить, публікація не відбувається. Помилку видно у вкладці Actions на GitHub.

Прогрес студента (галочки) зберігається в його браузері, окремо для кожної CJM.
